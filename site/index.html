atcli

AtCoder の問題を解くための CLI。取得からテスト、提出、コミットまでを一本のワークフローにまとめる。

$ nix run github:gesop0n/atcli -- --help

GitHub API ドキュメント

サニタイザ内蔵

デバッグビルドは ASan / UBSan 付き。範囲外アクセスは WA になる前に捕まる。

ビルドキャッシュ

コンパイラの版・フラグ・依存ヘッダを指紋にする。ライブラリを直せば作り直す。

提出まで一本

サンプル取得、ローカル判定、提出、コミットが同じ CLI にある。

診断

落ちた場所が、行で出る

サニタイザが標準エラー出力に書いた位置をそのまま読む。黙ったまま落ちた場合だけ LLDB / GDB で失敗ケースを再実行する。

$ atcli test
Built abc300_a [debug]
RE  sample-1             exit=signal: 6 (SIGABRT) (530.6 ms)
source:
  attempts/abc300/a/main.cpp:8
  8 |     for (int i = 0; i <= n; ++i) s += a[i];
stderr:

    #0 0x00010047caec in main main.cpp:8

判定

サンプルを回して、差分を見る

許容誤差を問題メタデータに書けば、数値トークンを絶対誤差と相対誤差の両方で比較する。.out のないケースは出力を表示するだけにとどめる。

$ atcli test
Cached abc300_a [debug]
AC  sample-1             (77.9 ms)
WA  sample-2             (75.6 ms)
--- expected / +++ actual
- 9
+ 0
RUN hand-1               (81.2 ms; no .out)
1 passed, 1 unchecked, 1 failed

ワークフロー

4 つのコマンド

  1. atcli new abc300 --cd

    問題一覧とサンプルを取得し、テンプレートから取り組みディレクトリを作って移動する。

  2. atcli test

    サンプルでローカル判定する。変更がなければ再ビルドしない。

  3. atcli submit

    提出相当の最適化でテストしてから提出し、ジャッジの結果が出るまで追う。

  4. atcli commit

    その取り組みと参照先の問題データだけをステージしてコミットする。

構成

4 つのクレート

atcli-judge は何も表示せず、判定結果を値として返す。他のクレートにも依存しないので、単体でも使える。

atcli-core

リポジトリの構造、設定、問題メタデータ。

atcli-atcoder

ログイン、セッションの保存、ページの取得と解析。

atcli-judge

コンパイル、実行、出力比較、停止位置の特定。

atcli

コマンドの組み立てと、端末への表示。
